![创建系统提示词资源](img/创建系统提示词资源.png)

(2) **挂载资源**

在会话设置中，将已创建的系统提示词资源挂载到当前会话。当系统提示词逻辑复杂且需要在多个会话间复用时，此功能尤为便捷。

![挂载系统提示词资源](img/挂载系统提示词资源.png)

(3) **版本控制**

资源支持版本管理与回滚，你可以主动保存为新版本，并可随时回退到历史版本。

![资源版本管理界面](img/资源版本管理界面.png)

### 消息模板资源

消息模板是一种更高效、特殊的 System Prompt——它将被插入到最新一轮用户消息中，使模型注意力高度集中在模板设定的内容上。

(1) **原理说明**

大模型的注意力天然集中在上下文的头部和尾部，中间部分容易被忽略。MamboChat 的消息模板将关键设定放在最新消息中，且可通过"参与长度"控制其生效轮次（设为 1 时仅当前轮生效），从而在不增加历史冗余的前提下强化特定设定。

(2) **新建与挂载**

创建消息模板资源后，在会话页面的输入框上方挂载该模板即可生效。

![挂载消息模板](img/挂载消息模板.png)

(3) **灵活使用**

随着会话进行，可以在输入框上灵活切换挂载的消息模板。例如：仅在需要代码输出时挂载代码规范的相关模板，而在规划架构时取消挂载。

![切换挂载的消息模板](img/切换挂载的消息模板.png)

Skill 是用于扩展 [Agent](#6-agent-配置与使用) 能力的技能包，可以定义一组工具、提示词和工作流程。

## 6. MCP 工具

MCP（Model Context Protocol）是一种标准化协议，允许 AI 模型通过统一接口调用外部工具和服务。通过配置 MCP 服务器，可以为 [Agent](#7-agent-配置与使用) 扩展丰富的工具能力。

### 新增 MCP 服务器

(1) **进入 MCP 管理页面**

在系统配置页面的"MCP 管理"区域，点击"新增"按钮。
![新增mcp](img/新增mcp.png)  
(2) **选择传输类型并填写配置**

MCP 支持两种传输方式：

| 传输类型 | 说明 | 适用场景 |
|---|---|---|
| **Stdio** | 通过本地命令启动子进程通信 | 本地运行的 MCP 服务（如 Python/Node 脚本） |
| **SSE** | 通过 HTTP Server-Sent Events 通信 | 远程或已作为服务运行的 MCP 服务端 |

- **Stdio 类型**：需填写 `Command`（执行命令，如 `python`、`node`、`uvx`）、`Args`（命令参数）和 `Env`（环境变量，如 API Key 等）
- **SSE 类型**：需填写服务的 `URL` 地址

(3) **测试连接**

填写完成后可点击"测试连接"按钮验证配置是否正确。测试成功后会显示该服务器提供的工具数量。

### 管理 MCP 服务器
![管理mcp服务器](img/管理mcp服务器.png)
MCP 服务器列表展示所有已配置的服务器信息，包括：

- **名称与描述**
- **传输类型**（STDIO / SSE）
- **启用状态**（ON / OFF）
- **健康状态**：绿色表示健康，红色表示异常，可通过刷新按钮重新检测
- **最后测试时间与错误详情**：连接失败时可查看具体错误堆栈

> 部分系统内置的 MCP 服务器标记为「系统」类型，不可编辑或删除。

### 管理工具
![管理工具](img/管理工具.png)
每个 MCP 服务器可以暴露多个工具。点击"查看工具"打开工具管理抽屉：

- **同步工具**：从 MCP 服务器拉取最新的工具列表
- **工具信息**：显示工具名称、描述和输入参数 Schema
- **在线状态**：标识工具是否可用（online / offline）
- **启用/禁用**：通过开关控制单个工具是否对 Agent 可见
- **审核模式**：
  - `none`：工具可直接被 Agent 调用，无需确认
  - `require_review`：Agent 调用该工具前需要用户确认（Human-in-the-Loop）
- **删除工具**：移除不需要的工具（仅离线工具可删除）

### 在 Agent 中使用

创建完 MCP 服务器并确保其健康状态正常后，在 [Agent](#7-agent-配置与使用) 配置中将该 MCP 服务器挂载即可。挂载后 Agent 将自动获取该服务器下所有已启用的工具，并在对话中根据需要调用。

### 在 Chat 中使用
在会话页面-普通模式,点击查看工具按钮选择使用
![在Chat中使用工具](img/在Chat中使用工具.png)

## 7. Agent 配置与使用

Agent 是 MamboChat v1.2.0 引入的核心能力，提供两种类型的智能体：

| 类型 | 说明                                                                                      | 适用场景 |
|---|-----------------------------------------------------------------------------------------|---|
| **ReAct Agent** | 基于工具调用的推理型 Agent,普通对话也是使用该Agent,但在Agent页面配置可用于DeepAgent的子Agent                          | 需要调用搜索、知识库、MCP 工具等完成任务 |
| **Deep Agent** | 基于 [deepagents](https://github.com/langchain-ai/deepagents) 项目的复杂功能型 Agent，具备文件读写、命令执行能力 | 代码开发、远程服务器运维 |

### 创建 Agent

(1) 进入配置页面的"Agent 管理"区域，点击新建 Agent。

![新建Agent入口](img/新建Agent入口.png)

(2) 选择 Agent 类型：
   - **ReAct Agent**：配置系统提示词、选择可用工具（MCP、知识库、ask_user 等）
   - **Deep Agent**：配置远程 Backend 连接信息，可选择 SSH 或 API Client 方式连接目标环境

![Agent类型选择与基础配置](img/Agent类型选择与基础配置.png)

(3) 为 Agent 配置资源：挂载知识库、Skill 技术包、MCP 服务器等扩展能力。

![Agent挂载资源](img/Agent挂载资源.png)

### 使用 Agent

在新建会话时直接关联 Agent。启用后，该会话的所有对话将由 Agent 驱动，自动调用工具完成复杂任务。
![在会话中启用Agent](img/在会话中启用Agent.png)

![Agent执行任务时的工具调用过程展示](img/Agent执行任务时的工具调用过程展示.png)

## 8. 远程 Backend 配置

远程 Backend 让 Deep Agent 能够访问外部环境（如 Linux 服务器或本地电脑），进行文件读写和命令执行。

### SSH Backend — 连接远程服务器

(1) 在配置页面的"Backend 管理"中新增 SSH 类型 Backend。 填写连接信息：主机地址、端口、用户名、认证方式（密码或密钥）。

<!-- TODO: 截图: SSH 连接信息填写 -->
![SSH连接信息填写](img/SSH连接信息填写.png)

(3) 测试连接成功后，将该 Backend 关联到 Deep Agent 即可使用。Agent 将通过 SFTP/SSH 远程读写文件、执行命令、浏览目录结构。

> **注意**：可配置编辑白名单/黑名单限制 Agent 可操作的目录范围，保障安全。

### API Client — 本地反向连接

如果希望 Agent 操作的是你本地电脑的文件（而非远程服务器），或者你的机器没有公网 IP，可以使用 API Client 模式：

(1) 在服务端配置页面新增 API 类型 Backend，记录生成的 `backend-id` 和 `api-key`。

![新增APIClient类型Backend](img/新增APIClient类型Backend.png)

(2) 在本地电脑上运行客户端程序（位于项目 `client/apibackend/` 目录）：

```bash
cd client/apibackend
pip install -r requirements.txt
python main.py --server-url ws://<你的服务器>:24911 --backend-id <backend-id> --api-key <key> --root-dir <要暴露的目录>
```
![运行APIClient](img/运行APIClient.png)

(3) 客户端连接成功后，Deep Agent 即可像操作远程服务器一样操作你本地的文件系统。
![APIClient运行状态与连接成功提示](img/APIClient运行状态与连接成功提示.png)
