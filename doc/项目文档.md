### **LLM-API 客户端系统 - 项目归档文档**

**文档版本:** 2.0
**归档日期:** 2025-10-12
**状态:** 核心功能及体验优化已完成

---

#### **1. 项目概述**

本项目是一个功能完善、配置灵活的 **LLM-API 客户端系统**。它允许用户连接并管理多个不同厂商的大语言模型（LLM），并通过一个统一、高效、健壮的界面与这些模型进行交互式聊天。

系统现已具备完整的服务商与模型管理、全局默认配置、层级化会话管理、精细化消息控制等核心功能，形成了一个稳定、易用且功能丰富的版本。

---

#### **2. 核心功能清单**

系统功能覆盖了从全局配置、服务商接入到高级聊天交互的全流程，具体可分为以下三大模块：

**2.1. 全局与服务商管理 (Settings 模块)**
*   **全局默认模型:**
    *   支持在独立的配置页面中指定一个“全局默认模型”。
    *   新创建的聊天会话将自动使用此默认模型。
    *   当会话原绑定的模型被删除时，系统会自动、静默地回退至全局默认模型，保证交互不中断。
*   **统一的服务商与模型管理:**
    *   **一体化创建:** 支持在单个弹窗内完成服务商的创建及其下属一个或多个模型的添加。
    *   **API 自动发现:** 对于兼容 OpenAI 规范的服务商，支持一键从其 API 自动获取可用模型列表，并以复选框形式供用户选择性添加。
    *   **连接测试:** 在配置服务商凭证时，提供“测试连接”功能，即时验证 API Host 和 Key 的有效性。
    *   **基础 CRUD:** 支持对服务商及其下的模型进行完整的增、删、改、查操作。
    *   **界面简化:** 隐藏了内部 UUID，为用户提供更简洁的配置体验。

**2.2. 会话与层级管理 (Chat 模块)**
*   **基础会话操作:**
    *   支持**新建**、**切换**和**删除**聊天会话。
    *   支持**复制**会话，快速创建包含完整历史消息的新会话。
*   **文件夹与层级管理:**
    *   支持在会话列表中**新建文件夹**，对会话进行分类。
    *   支持通过**拖拽**方式，自由调整会话和文件夹的顺序及层级关系。
*   **智能导航与持久化:**
    *   新建会话后，系统**自动跳转**至新会话。
    *   打开应用时，系统**自动加载最近一次查看的会话**。
    *   用户在输入框中未发送的内容，在切换会话后会**自动缓存和恢复**。

**2.3. 聊天交互与消息控制 (Chat 模块)**
*   **核心聊天功能:**
    *   支持通过流式 API (`Server-Sent Events`) 实时渲染 AI 回复。
    *   允许在聊天中随时**更换当前会话绑定的 AI 模型**。
    *   支持为每个会话独立配置 **System Prompt** 及 **模型参数** (如 Temperature, Top P)。
*   **生成过程控制:**
    *   在 AI 生成过程中，提供**中断生成**功能。
    *   支持对 AI 的最新回复进行**重新生成**。
*   **精细化消息操作 (悬浮菜单):**
    *   **通用操作:** 支持对任意消息进行**复制**和**删除**。
    *   **消息编辑:**
        *   支持编辑用户和 AI 的消息内容。
        *   针对用户消息，提供“**保存并重新发送**”功能，该操作会更新消息内容、删除后续对话并立即触发新一轮生成。
    *   **增强的重新生成:**
        *   **从 AI 消息处重新生成:** 删除当前 AI 消息及其后的所有对话，并重新生成。
        *   **从用户消息处重新生成:** 删除该用户消息之后的所有对话，并重新生成。

#### **3. 技术栈与架构**

*   **后端:** `Python`, `FastAPI`, `SQLite`
*   **前端:** `Vue 3` (Composition API, `<script setup>`), `Vite`, `TypeScript`
*   **UI 组件库:** `Element Plus`
*   **HTTP 客户端:** `axios` (标准 API), `@microsoft/fetch-event-source` (SSE 流式处理)
*   **状态管理:** `Pinia`
*   **Markdown 渲染:** `markdown-it` (支持代码高亮)

**3.1. 架构简介**

项目采用**前后端分离**架构：
*   **后端 (Backend)**: 使用 FastAPI 构建，负责提供 RESTful API 和 Server-Sent Events (SSE) 流式接口。它处理所有业务逻辑，包括数据库操作 (CRUD)、与外部 LLM API 的交互等。
*   **前端 (Frontend)**: 使用 Vue 3 构建的单页面应用 (SPA)，负责用户界面的渲染和交互。通过 Pinia 进行全局状态管理，调用后端 API 完成数据交互。

#### **4. 后端设计与实现**

**4.1. 数据模型与持久化 (`models.py`, `crud.py`)**
*   **模型设计:** 数据库设计了 `AIProvider`, `AIModel`, `Chat`, `Message`, `GlobalSettings` 五个核心模型。`GlobalSettings` 表以键值对形式存储系统级配置（如 `default_model_id`）。
*   **健壮性设计:** 在 `delete_model` 操作中，会将所有使用该模型的会话 `aiModelId` 字段置为 `NULL`，为上层 API 的回退逻辑提供基础。
*   **事务性操作:** `create_provider_with_models` 函数确保了服务商及其关联模型被原子性地创建。

**4.2. API 路由 (`routers/`)**
*   **职责划分:** API 路由被清晰地划分为三个模块：`chats.py`, `providers_models.py`, `settings.py`。
*   **核心接口:**
    *   `providers_models.py`: 提供了 `POST /providers/fetch-models` (获取外部模型) 和 `POST /providers/test-connection` (连接测试) 等高级功能接口。
    *   `settings.py`: 提供 `GET/PUT /settings/global` 接口，用于管理全局配置。
*   **模型回退逻辑:** `chats.py` 中的 `GET /chats/` 和 `GET /chats/{chat_id}/messages` 两个接口均实现了**默认模型回退**。当检测到会话的 `aiModelId` 无效或为空时，会在响应中自动替换为全局默认模型的 ID，确保前端始终能获取到有效的模型引用。

**4.3. 核心服务 (`services/llm_service.py`)**
*   新增 `fetch_models_from_provider` 函数，负责调用外部 `/v1/models` 接口，是实现模型自动发现和连接测试功能的核心。
*   `generate_chat_response` 等函数在执行前会检查会话是否绑定模型，若无则尝试从数据库加载并应用全局默认模型。

#### **5. 前端设计与实现**

**5.1. 状态管理 (`stores/`)**
*   **`providerStore.ts`:**
    *   管理服务商、模型及全局配置 (`globalSettings`)。
    *   新增 `reconcileChatModels` 核心 action。该方法在 `fetchProviders` 成功后被调用，会主动检查 `chatStore` 中的所有会话，将指向无效或已删除模型的 `aiModelId` 修正为全局默认模型 ID，实现了**前端状态的自动同步与修复**。
*   **`chatStore.ts`:**
    *   在创建新会话 (`createNewItem`) 时，若未指定模型，会自动从 `providerStore` 获取并应用全局默认模型。

**5.2. 路由与视图 (`router/`, `views/`)**
*   `SettingsView.vue` 视图被重构为使用 `El-Tabs` 标签页布局，清晰地分离了“服务商与模型管理”和“全局配置”两大功能区。

**5.3. 核心组件 (`components/`)**
*   **`settings/` 目录:**
    *   `ProviderManager.vue` 和 `ModelManager.vue` 被重构并合并为统一的 **`ProviderModelManager.vue`** 组件，提供了包括一体化创建、API获取模型、连接测试等所有服务商相关操作的流畅体验。
    *   新增 **`GlobalSettings.vue`** 组件，为用户提供了设置全局默认模型的简洁界面。
*   **`chat/` 目录:**
    *   `ChatWindow.vue` 及其子组件现在能够无缝地处理模型被删除的场景。得益于后端 API 的回退逻辑和前端 `providerStore` 的状态同步机制，即使用户在设置页删除了当前模型，返回聊天页后，界面也能正确显示并使用全局默认模型，无需刷新页面。
