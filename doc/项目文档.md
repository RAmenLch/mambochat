### **LLM-API 客户端系统 - 第一阶段项目归档文档**

**文档版本:** 1.1
**归档日期:** 2025-10-10
**状态:** 第一阶段核心功能及体验优化已完成

---

#### **1. 项目概述**

本项目旨在开发一个功能完善的 **LLM-API 客户端系统**。它允许用户连接并管理多个不同厂商的大语言模型（LLM），并通过统一、高效的界面与这些模型进行交互式聊天。

第一阶段已成功搭建了应用的核心框架，实现了服务商与模型管理、完整的聊天交互流程，并通过三次体验优化迭代，加入了会话层级管理、精细化消息控制等高级功能，形成了一个稳定、功能丰富的可用版本。

---

#### **2. 核心功能清单**

本阶段完成的功能已覆盖从基础配置到高级交互的全流程，具体可分为以下三大模块：

**2.1. AI 服务商与模型管理 (Settings 模块)**
*   **服务商配置 (Provider):** 在独立的设置页面中，支持对 AI 服务提供商进行增、删、查、改。配置信息包括：服务商名称、API Host、API Key。
*   **模型配置 (Model):** 支持为每个服务商添加、删除和查看其下的具体 AI 模型。配置信息包括：模型显示名称、模型 ID (如 `gpt-4o`)。

**2.2. 会话与层级管理 (Chat 模块)**
*   **基础会话操作:**
    *   支持**新建**、**切换**和**删除**聊天会话。
    *   支持**复制**会话，快速创建包含完整历史消息的新会话。
*   **文件夹与层级管理:**
    *   支持在会话列表中**新建文件夹**，对会话进行分类。
    *   支持通过**拖拽**方式，自由调整会话和文件夹的顺序及层级关系。
*   **智能导航与持久化:**
    *   新建会话后，系统**自动跳转**至新会话。
    *   打开应用时，系统**自动加载最近一次查看的会话**。
    *   用户在输入框中未发送的内容，在切换会话后会**自动缓存和恢复**。

**2.3. 聊天交互与消息控制 (Chat 模块)**
*   **核心聊天功能:**
    *   支持通过流式 API (`Server-Sent Events`) 实时渲染 AI 回复。
    *   允许在聊天中随时**更换当前会话绑定的 AI 模型**。
    *   支持为每个会话独立配置 **System Prompt** 及 **模型参数** (如 Temperature, Top P)。
*   **生成过程控制:**
    *   在 AI 生成过程中，提供**中断生成**功能。
    *   支持对 AI 的最新回复进行**重新生成**。
*   **精细化消息操作 (悬浮菜单):**
    *   **通用操作:** 支持对任意消息进行**复制**和**删除**。
    *   **消息编辑:**
        *   支持编辑用户和 AI 的消息内容。
        *   针对用户消息，提供“**保存并重新发送**”功能，该操作会更新消息内容、删除后续对话并立即触发新一轮生成。
    *   **增强的重新生成:**
        *   **从 AI 消息处重新生成:** 删除当前 AI 消息及其后的所有对话，并重新生成。
        *   **从用户消息处重新生成:** 删除该用户消息之后的所有对话，并重新生成。

#### **3. 技术栈与架构**

*   **后端:** `Python`, `FastAPI`, `SQLite`
*   **前端:** `Vue 3` (Composition API, `<script setup>`), `Vite`, `TypeScript`
*   **UI 组件库:** `Element Plus`
*   **HTTP 客户端:** `axios` (标准 API), `@microsoft/fetch-event-source` (SSE 流式处理)
*   **状态管理:** `Pinia`
*   **Markdown 渲染:** `markdown-it` (支持代码高亮)

**3.1. 架构简介**

项目采用**前后端分离**架构：
*   **后端 (Backend)**: 使用 FastAPI 构建，负责提供 RESTful API 和 Server-Sent Events (SSE) 流式接口。它处理所有业务逻辑，包括数据库操作 (CRUD)、与外部 LLM API 的交互等。
*   **前端 (Frontend)**: 使用 Vue 3 构建的单页面应用 (SPA)，负责用户界面的渲染和交互。通过 Pinia 进行全局状态管理，调用后端 API 完成数据交互。

#### **4. 后端设计与实现**

**4.1. 数据模型与持久化 (`models.py`, `crud.py`)**
*   **模型设计:** 数据库设计了 `AIProvider`, `AIModel`, `Chat`, `Message` 四个核心模型，通过外键关联。`Chat` 模型通过 `itemType`, `parentId`, `sortOrder` 等字段支持了文件夹、层级和排序功能。
*   **数据操作:** `crud.py` 文件封装了所有对数据库的异步读写操作，为上层路由提供了清晰、可复用的数据访问接口。

**4.2. API 路由 (`routers/`)**
*   **职责划分:** API 路由被清晰地划分为两个模块：
    *   `chats.py`: 处理所有与聊天交互相关的功能，包括会话管理、消息操作和 AI 内容生成。
    *   `providers_models.py`: 负责处理设置页面中的 AI 服务商和模型配置的 CRUD 操作。
*   **核心接口:** `chats.py` 中提供了丰富的原子化 API，如 `POST /chats/reorder` (批量排序)、`POST /chats/{chat_id}/regenerate-from/{msg_id}` (从指定消息重新生成) 等，以支持前端复杂的交互需求。

**4.3. 核心服务 (`services/llm_service.py`)**
*   该服务是与外部大语言模型 API 通信的桥梁。
*   它负责根据当前会话的配置（模型、System Prompt、参数）和历史消息，动态构建请求体。
*   实现了 `generate_chat_response` (流式) 和 `generate_chat_response_non_stream` (非流式) 两个核心方法，处理 HTTP 请求、解析响应并将其返回给前端。

---

#### **5. 前端设计与实现**

**5.1. 状态管理 (`stores/`)**
*   **双 Store 结构:**
    *   `chatStore.ts`: 作为前端业务逻辑的核心，管理聊天列表、当前会话、消息、生成状态等，并封装了所有复杂的聊天交互 action。
    *   `providerStore.ts`: 负责管理服务商和模型数据，为设置页面和聊天页面的模型选择器提供数据支持。
*   **流式处理:** `chatStore` 中使用 `@microsoft/fetch-event-source` 处理 SSE 流，并通过 `AbortController` 实现了中断生成功能，确保了交互的流畅性和资源的有效利用。

**5.2. 路由与视图 (`router/`, `views/`)**
*   `ChatView.vue` 和 `SettingsView.vue` 作为顶层视图，分别组织和布局了各自功能模块下的子组件。

**5.3. 核心组件 (`components/`)**
*   **`chat/` 目录:**
    *   `ChatList.vue`: 使用 `El-Tree` 实现可拖拽的树状会话列表，并集成右键菜单。
    *   `ChatWindow.vue`: 聊天主窗口，管理会话设置抽屉和输入框缓存。
    *   `MessageItem.vue`: 渲染单条消息，使用 `markdown-it` 实现 Markdown 格式化和代码高亮，并提供悬浮操作菜单。
*   **`settings/` 目录:**
    *   `ProviderManager.vue` 和 `ModelManager.vue`: 负责渲染和管理设置页面中的服务商和模型列表，提供增删改查的 UI 界面。
